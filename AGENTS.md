# AGENTS.md

Zugriff in Zig: the macOS command palette of `zugriff-menu-rust` (Rust and
GPUI), rebuilt in Zig 0.17.1 on nanoui (pinned in `build.zig.zon`). What it does, its commands
and its layout are in `README.md`. The Rust version's `PRODUCT.md` owns the product intent; this
port follows it and names its differences in `README.md`.

## Opening contract

The palette opens before any content work; this is not negotiable.

- Create the panel and register the global hot keys before the installed-app scan or any other
  file work starts. Discovery never runs on the main thread or in the start path.
- The palette starts with an empty catalog and a loading state. Typing stays possible; when the
  background catalog arrives, the current query is applied.
- A show only places and orders the pre-created panel. It never waits for a scan, a search,
  icon rendering or a fresh catalog.
- Keep the non-activating panel: the app in front keeps its focus while the palette is open.

## Zig

- Before writing or reviewing Zig code, load the skill `zig` (the shared agent skill for Zig 0.17).
- Never write std, build or nanoui APIs from memory. Check them in the source: std through
  `zig env` (`.std_dir`), nanoui in `zig-pkg/nanoui-*/src`. Its tests (`src/ui/tests*.zig`,
  `src/ui/tester.zig`) are the best examples.
- Which source wins: compiler and these rules, then the pinned nanoui source, then the std source,
  then the skill.
- The toolchain comes from `mise.toml` and `mise.lock`; run commands through mise (`mise x -- zig …`).
  `minimum_zig_version` is advisory only: Zig does not enforce it.
- Do not use `nui start` or `zigdoc @init`; they generate a different project layout.
- `src/core/emoji_data.zig` is generated by `scripts/emoji_data.py`; never edit it by hand.

## Changesets and releases

- Read `CONTRIBUTING.md` before committing. Every commit adds a new changeset in `.changeset/`
  with an explicit `type` and `bump`; docs, tests, tooling and refactoring add an explicit empty
  one (`python3 -B scripts/changeset.py add --empty`). Stage it in the same commit; never bypass
  the pre-commit hook.
- The version is the `.version` line of `build.zig.zon`. Only `make version` changes it, on a clean
  `main` and only when a release is asked for; commit that as `version bump to vX.Y.Z`.
- No push, tag or hosted release without an explicit request.
- There is no install target yet.

## Checks

- `make verify` before every commit: the changeset tests and status, then `mise run check` (build,
  `zig fmt --check`, the tests in Debug and ReleaseSafe, and ziglint).
- ziglint (`.ziglint.zon`, `mise run lint`) fails `check` on any finding. Fix the finding; do not
  weaken the task or `.ziglint.zon` to get past it.
- The tests render the palette offscreen with `ui.Tester` and may run on this Mac. They open no
  window, register no hot key, post no key events and touch neither the clipboard nor the icon
  cache.
- The real agent (`zig build run`, `zig-out/bin/zugriff`) takes the global hot keys, shows a
  panel over everything and can post `⌘V` to other apps. Run it only on a separate test Mac,
  never on the developer's Mac,
  and with its own `HOME` so it does not meet the installed Rust agent's socket and preferences.

## Never

- No contributions to Zig itself (code, issues, comments, chat) written or found with an LLM:
  the Zig Code of Conduct forbids it.
